# P4 testgen validation server

## Build the Docker image first (required)

The server starts **36 Docker containers** using the image `p4_test_suite`. That image is not on Docker Hub; you must build it locally. From this directory:

```bash
cd /path/to/PINC/code/server-validation/p4testgen-server
docker build -t p4_test_suite .
```

On **Apple Silicon (M1/M2/M3)** the Dockerfile uses `--platform=linux/amd64` so the build works (the p4lang/p4c image has no arm64 variant). The build can take a while (base image, cloning p4c, installing deps). When it finishes, start the server (see below).

## Run the FastAPI server (from this directory)

Install dependencies and run **using the same Python** (so the reloader sees your packages). From the repo root venv:

```bash
cd /path/to/PINC/code/server-validation/p4testgen-server
pip install -r requirements.txt
# Use the venv's Python so uvicorn and the reloader subprocess both see httpx, etc.:
python -m uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

If you still get `ModuleNotFoundError: No module named 'httpx'`, the shell may be using a different `uvicorn` (e.g. Homebrew Python 3.14). Run explicitly with the project venv:

```bash
/path/to/PINC/.venv/bin/python -m uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

Do **not** run `uvicorn main:app` from `server-validation/` — `main.py` is inside `p4testgen-server/`, so you must be in `p4testgen-server` for the import to work.

## What this server does

- **POST /validate** with body `{"code": "<p4 source string>"}`: runs the P4 program through the test pipeline inside a Docker container (build image first; see Dockerfile).
- The container runs `run_tests.sh`, which uses **p4testgen** to generate PTF test cases, then runs them. The server is used by the research experiments (e.g. pass@k), not by the Initial Wrapper.

## Test case generation (in this repo)

Test cases are **not** generated by the Intent → P4 wrapper. They are generated by **p4testgen** (from the p4c toolchain) in:

1. **`code/server-validation/p4testgen-server/run_tests.sh`** (lines 53–56): runs `p4testgen` → writes PTF tests to `out-p4testgen/`, then runs PTF.
2. **`p4et/Shell Script/script.sh`** (lines 51–54): same idea for local/p4et usage.

The Initial Wrapper only compiles P4 with p4c (`validate_p4.sh`); it does not run p4testgen or PTF.
